# Cloudly: дизайн-спека

Платформа: **Android, Jetpack Compose**. Живой референс: `prototype/index.html` (открывается в браузере, все числа ниже взяты из него).

Единицы: 1 px прототипа = 1 dp / 1 sp. Холст прототипа 390×844.

## 1. Идея

Тёмное дымчатое стекло. Единственный источник света в приложении это обложка играющего трека.

Четыре правила, из которых выводится всё остальное:

1. **Тьма.** Фон почти чёрный. Яркими бывают только обложка, один акцентный цвет и активное действие.
2. **Свет из обложки.** Три цвета извлекаются из обложки и красят свечение фона, hero-карточку, кнопку Play, волну и кольцо загрузки в списках. Новый трек даёт новую атмосферу.
3. **Стекло только для того, что парит, и оно бесцветное.** Док, мини-плеер, панели, тосты, поле поиска. Списки и карточки контента стеклом не являются. Цвет обложки на стекло не накладывается: он виден сквозь него, но сама поверхность, обод и индикаторы нейтральные.
4. **Всё на пружинах и управляется жестом.** Ничего не появляется скачком. Любую анимацию можно перехватить пальцем.

Зерно лежит на фоне и на плитках, под контентом и под стеклом. Оно нужно не только для эстетики: убирает бандинг на тёмных градиентах. Тексты, обложки и кнопки зерна не получают.

## 2. Стек

| Задача | Решение |
|---|---|
| UI | Jetpack Compose, Material 3 только как база (тема, доступность). Свои компоненты. |
| Стекло | **`io.github.kyant0:backdrop`** (репозиторий Kyant0/AndroidLiquidGlass), см. раздел 5 |
| Зерно | AGSL `RuntimeShader` (API 33+), запасной вариант: тайл-битмап |
| Аудио | Media3 (ExoPlayer + MediaSessionService). FLAC, Opus, MP3 поддерживаются. |
| Картинки | Coil 3, миниатюры 176 px, большая обложка 640 px |
| Цвет из обложки | свой квантизатор (порт из прототипа, ~40 строк) или `material-color-utilities` |
| Загрузки | WorkManager + OkHttp, файлы в app-specific storage; Media3 `DownloadService` как альтернатива |
| Хранилище | Room (треки, загрузки, избранное), DataStore (настройки) |

Почему не Flutter: платформа только Android, а у Compose есть готовая библиотека жидкого стекла и нативная связка с Media3. На Flutter эффекты пришлось бы писать шейдерами самим.

### 3.2 Динамика из обложки

Три цвета, живут в `CompositionLocal` `LocalCoverPalette`:

| Токен | Что это | Диапазон (HSL) | Где |
|---|---|---|---|
| `glow` | главный цвет обложки | S 0,62–0,95; L 0,56–0,68 | кнопка Play, волна, выбранный чип, кольцо загрузки в списках, свечение фона и hero |
| `echo` | второй цвет, отстоит по тону ≥ 50° | S 0,50–0,90; L 0,34–0,50 | свечение фона, плашка «Echo» |
| `deep` | тот же тон, что у `glow` | S 0,50; L 0,10 | низ шторки плеера, подложка фона. На стекло не идёт |

Алгоритм (так сделано в прототипе):

1. Обложку уменьшить до 40×40.
2. Пиксели с S < 0,2 или L < 0,12 или L > 0,92 отбросить.
3. Остальные разложить в 18 корзин по тону (шаг 20°), вес пикселя = `S^1.2 · (1 − |L − 0,55| · 1,7)`.
4. `glow` = взвешенное среднее самой тяжёлой корзины. `echo` = самая тяжёлая корзина, отстоящая по тону на 50° и больше. Если такой нет, берётся тон `glow` + 38°.
5. Привести S и L к диапазонам из таблицы. Это важно: без нормализации тусклые обложки дают тусклый интерфейс, а кислотные слепят.

Переход между треками: интерполяция всех трёх цветов пружиной **Glide** (около 0,25–0,3 с). Не кроссфейд двух слоёв, а именно интерполяция цвета, иначе в середине перехода серая каша.

Кэш: по `trackId`. Если бэкенд отдаёт `palette` вместе с треком, клиент ничего не считает, и цвета в списках появляются сразу.

Проверки контраста:
- текст на `deep`-тонированном стекле: не ниже 4,5:1;
- иконка на кнопке Play и в выбранном чипе: цвет выбирается расчётом, чернила `#0A0A0E` или белый, что даёт контраст не ниже 4,5:1. Чернила хороши почти везде, но на синих и фиолетовых `glow` с L около 0,56 дают меньше 4,5:1, и тогда иконка становится белой (в прототипе это переменная `--on-glow`).

## 5. Материалы

### 5.1 Стекло

Движок: **Backdrop (Kyant0)**, Apache-2.0, Compose-нативная библиотека. Она не даёт готовых компонентов, только эффекты, поэтому `GlassSurface` пишем сами.

> Что проверено, а что нет. Страницу репозитория я открыл: артефакт `io.github.kyant0:backdrop`, Apache-2.0, около 4,5 тыс. звёзд, 37 открытых issues, в README ссылки на примеры `LiquidButton`, `LiquidToggle`, `LiquidSlider`, `LiquidBottomTabs`. Документацию (kyant.gitbook.io) и номера версий из этой среды открыть не удалось. Сигнатуры в наброске ниже даны по памяти, их нужно сверить с документацией и каталогом примеров перед использованием. Минимальные API ориентировочно такие: блюр с API 31, линза и вибрантность с API 33. Тоже сверить.

Слои стеклянной поверхности, снизу вверх (значения из прототипа):

| # | Слой | Значение |
|---|---|---|
| 1 | Размытие фона | 20 dp (диапазон настройки 12–28) |
| 2 | Вибрантность | насыщенность ×1,7 |
| 3 | Линза (рефракция края) | зона 20–26 dp, смещение до 12–16 dp, только у поверхностей высотой ≥ 56 dp |
| 4 | Тонировка | нейтральная: `#0E0E12` @ 46%, сверху белый градиент 11% → 3,5% → 6% по вертикали. Цвета обложки здесь нет |
| 5 | Нижний отсвет | внутренняя тень вверх на 12 dp, белый @ 7% |
| 6 | Обод | 1 dp, вертикальный градиент белого 30% → 5% → 5% → 18% |
| 7 | Блик | радиальный белый @ 95% на ободе, 190×90 dp, следует за вектором света |
| 8 | Тень | 0 16 36 −12 чёрный 70% + 0 1 3 чёрный 40% |

Правило цвета: стекло бесцветное. Элементы на нём тоже нейтральные: кольцо загрузки на панели плеера, прогресс мини-плеера, точка в бейдже качества, индикатор таб-бара и сегмента белые. Цвет обложки остаётся на фоне за стеклом и в контенте (кнопка Play, волна, плитки).

Вектор света: на Android берётся из акселерометра / rotation vector с фильтром низких частот (отклонение телефона двигает блик и наклон обложки до ±5–7°). Без датчика, при Reduce motion или в покое: медленный дрейф по синусоиде.

Где стекло разрешено: док (таб-бар и мини-плеер), панель действий плеера, поле поиска, сегмент-контрол, тосты, шторка очереди. Больше четырёх стеклянных поверхностей на экране одновременно не делать.

Набросок (проверить сигнатуры по документации):

```kotlin
val backdrop = rememberLayerBackdrop()

Box(Modifier.fillMaxSize().layerBackdrop(backdrop)) {
    // aurora + контент экрана
}

@Composable
fun GlassSurface(
    backdrop: Backdrop,
    modifier: Modifier = Modifier,
    shape: Shape = RoundedCornerShape(32.dp),
    content: @Composable BoxScope.() -> Unit,
) {
    Box(
        modifier.drawBackdrop(
            backdrop = backdrop,
            shape = { shape },
            effects = {
                vibrancy()
                blur(20.dp.toPx())
                lens(refractionHeight = 22.dp.toPx(), refractionAmount = 16.dp.toPx())
            },
            onDrawSurface = { drawGlassTint() },   // слои 4–7, без цвета обложки
        ),
        content = content,
    )
}
```

Деградация по версиям Android:

| Уровень | Что включено |
|---|---|
| API 33+ | блюр + вибрантность + линза |
| API 31–32 | блюр + тонировка, без линзы |
| ниже | непрозрачная подложка `deep` @ 88% + обод + отсвет. Блюра нет |

Настройка «Уменьшить прозрачность» в приложении переключает всё на нижний уровень.

Альтернатива: Haze (chrisbanes/haze) умеет блюр на API 23+ и в версии 2.x получил модули стекла, но по найденным источникам это alpha и экспериментальный API. Я не рекомендую строить на нём ядро. Подходит как запасной вариант блюра для старых версий, если решим держать minSdk ниже 31.

### 5.2 Зерно

Зерно принадлежит фону. Порядок слоёв: `ink` → свечение → **зерно** → виньетка → контент → стекло. То же зерно статичным слоем лежит на hero и плитках. Стекло размывает зернистый фон, поэтому на самой панели зерно не рисуется. Обложки зерна не получают (в прототипе у них только лёгкий дизеринг). Слой не перехватывает касания.

Параметры (из прототипа, слайдер 50%): вспышки белого и чёрного в равных долях, альфа пикселя = `|n − 0,5|·2` в квадрате, максимальная альфа 0,18. Обновление 10–12 раз в секунду (рывками, как плёнка, а не плавно).

AGSL (API 33+):

```kotlin
private const val GRAIN = """
uniform float seed;
uniform float amount;
half4 main(float2 p) {
    float n = fract(sin(dot(p + seed, float2(12.9898, 78.233))) * 43758.5453);
    float a = pow(abs(n - 0.5) * 2.0, 2.0) * amount;
    half3 c = n > 0.5 ? half3(1.0) : half3(0.0);
    return half4(c * a, a);          // premultiplied
}
"""

@Composable
fun GrainOverlay(amount: Float = 0.18f, fps: Int = 12) {
    val shader = remember { RuntimeShader(GRAIN) }
    var seed by remember { mutableFloatStateOf(0f) }
    LaunchedEffect(Unit) { while (true) { seed = Random.nextFloat() * 1000f; delay(1000L / fps) } }
    Canvas(Modifier.fillMaxSize()) {
        shader.setFloatUniform("seed", seed)
        shader.setFloatUniform("amount", amount)
        drawRect(ShaderBrush(shader))
    }
}
```

Ниже API 33: заранее сгенерированный тайл 200×200 как `BitmapShader` с `TileMode.REPEAT`, смещение тайла случайное раз в 83 мс. Значение `amount` подобрать на реальном устройстве, на OLED зерно выглядит сильнее, чем на мониторе.

### 5.3 Свечение (aurora)

Две большие окружности (190% ширины экрана) с двумя радиальными градиентами каждая. Вращаются вокруг своего центра: 46 с и 64 с на оборот, вторая в обратную сторону, линейно. Блюра нет: радиальные градиенты и так мягкие, это дёшево.

Цвета: первая окружность `glow` и `echo`, вторая светлый `glow` и `deep`.

| Контекст | Центр вращения | Видимость |
|---|---|---|
| Фон экранов | над верхним краем экрана | 55%, маска сверху вниз до 62% высоты |
| Шторка плеера | около обложки (y ≈ 250–320 dp) | 100%, снизу затемнение 62% |

Реализация: `Canvas` с `drawCircle(brush = Brush.radialGradient(...))`, угол из `rememberInfiniteTransition`. Читать угол только в фазе отрисовки (`graphicsLayer { rotationZ = angle }`), чтобы не вызывать рекомпозицию.

## 7. Движение

### 7.1 Пружины

Единственный источник движения. Числа одинаковы в прототипе и в Compose (масса 1).

| Токен | dampingRatio | stiffness | Где |
|---|---|---|---|
| `Glide` | 0,85 | 400 | палитра, появление, переключения, строки текста |
| `Sheet` | 0,80 | 150 | шторка плеера, обложка, очередь |
| `Snap` | 0,60 | 1500 | нажатия, иконки |
| `Liquid` | 0,55 | 300 | индикатор таб-бара и сегмента |

```kotlin
object Motion {
    val Glide  = spring<Float>(dampingRatio = 0.85f, stiffness = 400f)
    val Sheet  = spring<Float>(dampingRatio = 0.80f, stiffness = 150f)
    val Snap   = spring<Float>(dampingRatio = 0.60f, stiffness = 1500f)
    val Liquid = spring<Float>(dampingRatio = 0.55f, stiffness = 300f)
}
```

Кроме пружин допускаются: бесконечные линейные циклы (aurora, 46–64 с), прыжки зерна, эквалайзер (0,8–1,15 с), экспо-ease-out `cubic-bezier(.22,1,.36,1)` для входа блоков 0,9 с.

### 7.2 Фирменные моменты

| Момент | Что происходит |
|---|---|
| **Шторка плеера** | Один прогресс `p` (0 → 1) управляет всем. Клип поднимается из мини-плеера (вырез от плашки 358×66 до полного экрана, радиус 33 → 48). Обложка по прямой летит из позиции 44×44 в 328×328 (радиус 14 → 38). Док уезжает вниз и гаснет, экран позади уменьшается до 94% и темнеет до 78%. Элементы плеера появляются по очереди с шагом 0,05 по `p`. Жест: тянуть мини-плеер вверх, 540 dp хода, за границей 0 и 1 резинка 22%. Отпускание: пружина `Sheet` с начальной скоростью жеста, цель 1, если `p + v·0,16 > 0,5`. Из-за недодемпфирования обложка слегка «дышит» у границы. |
| **Смена трека** | Новая обложка выезжает с поворотом ±3° и блюром 12 px → 0 за 0,64 с, старая уходит в противоположную сторону. Название и артист: старое уходит вверх на 10 dp, новое поднимается на 14 dp. Палитра интерполируется (Glide). Волна и текст песни пересоздаются. |
| **Индикатор дока** | Пружина `Liquid` по позиции. Ширина растёт от скорости: `w + min(46, |v|·0,045)`, высота чуть сжимается. Получается капля, которая тянется за пальцем. |
| **Волна** | 64 столбика. Проигранные закрашены `glow` и светятся у головки. Под пальцем столбики вырастают по гауссиане (σ ≈ 36 dp, до +50%). Пока играет, рядом с головкой лёгкая пульсация. Над пальцем всплывает стеклянный пузырь с временем. |
| **Текст песни** | Активная строка 100%, остальные темнеют и размываются пропорционально расстоянию (до 5 px), уменьшаются до 90%. Контейнер плавно центрирует активную строку (0,8 с, ease-out). Тап по строке перематывает. Для TalkBack размытие отключать. |
| **Режимы плеера** | «Текст»: обложка сжимается до 56 dp в левый верхний угол, заголовок уезжает наверх и уменьшается до 74%. «Очередь»: обложка 200 dp вверху, снизу выезжает стеклянная шторка с 316 dp. Оба режима на пружинах `Glide` / `Sheet`. |
| **Скачивание** | Иконка → кольцо с прогрессом (обводка 2 dp, цвет `glow`) → при готовности кольцо уходит, заливается круг `glow` с пружинным «выскоком» и галочка. Тост с обложкой выезжает сверху с пружиной. |
| **Первый вход на главную** | Секции поднимаются на 22 dp с блюром 8 → 0 и шагом 80 мс. Один раз. |
| **Нажатие** | Масштаб 0,95 за 0,1 с вниз, возврат за 0,55 с с перелётом. |

Всё, что завязано на `p`, читать в фазе layout / draw (`graphicsLayer {}`, `Modifier.layout`), не в композиции, иначе жест будет дёргаться.

## 8. Экраны

Нижняя навигация: Главная, Поиск, Медиатека. Над ней мини-плеер (виден, пока есть текущий трек). Плеер открывается шторкой поверх всего.

### 8.1 Главная
- Заголовок: дата (label) и приветствие по времени суток (displayXL, курсив). Справа стеклянная кнопка настроек.
- **Hero «Вечерний микс»** 226 dp, радиус 34 (название по времени суток). Краски из палитры играющего трека (`glow` и `echo`) на тёмной подложке, зерно, затемнение снизу. Подпись «На основе «название трека»». Меняет цвет вместе с палитрой. Кнопка «Слушать» на стекле запускает первую рекомендацию.
- **«Рекомендуем»**: лента карточек 150 dp со snap. Под каждой обложкой название (Cormorant), артист и **причина** мелким caps: «Из «Ночной город»», «Тот же жанр», «Похожее настроение», «Тоже Hi-Res», «Новое для вас». Лента пересчитывается при смене трека и въезжает справа с размытием.
- «Недавно»: строки списка. Формат всегда виден (бейдж), Hi-Res подсвечен `glow`.
- «Настроения»: плитки 104 dp. Тёмная подложка, мягкое свечение одного приглушённого оттенка (S 45–55%, L 30–44%), зерно. Нажатие запускает подборку.

Алгоритм рекомендаций (в прототипе, на клиенте): оценка трека = 3, если он в одном плейлисте с текущим, + 3 за тот же жанр, + 2 за близкий тон палитры (разница до 40°) или + 1 (до 80°), + 1, если оба Hi-Res. Причина берётся по приоритету: плейлист, жанр, настроение, качество. Показываются 6 лучших. В продукте тот же интерфейс получает список с сервера, причина приходит полем.

### 8.2 Поиск
- Стеклянное поле 54 dp. Результаты фильтруются по мере ввода.
- Фильтры-чипы: Всё, Hi-Res, Скачано. Выбранный чип заливается `glow`.
- Пустой запрос: плитки жанров разной высоты (100 и 130 dp), такие же приглушённые, как плитки настроений.
- Пустая выдача: «Ничего не нашлось. Попробуйте другое слово или снимите фильтр.»

### 8.3 Медиатека
- Сегмент-контрол «Плейлисты / Альбомы / Скачано» с индикатором `Liquid`.
- Плейлисты: сетка 2 колонки, обложка-стопка из трёх карточек с поворотами −9° / 6° / −2°.
- Скачано: стеклянная панель хранилища (число displayM, составной бар по форматам: Hi-Res FLAC цветом `glow`, FLAC цветом `echo`, MP3 серым) и список.

### 8.4 Плеер
Координаты (dp) при полностью открытой шторке:

| Элемент | Позиция |
|---|---|
| Верхняя панель | y 52, высота 44: свернуть, «Из альбома» + название, меню |
| Обложка | 31, 112, 328×328 |
| Название и артист | y 466, ширина 328; справа сердце 48 dp |
| Волна | y 548, 328×48 |
| Время / бейдж качества / остаток | y 604; бейдж по центру на стекле, формат + «Hi-Res» |
| Управление | y 640, высота 76: перемешать, назад, Play 76 dp, вперёд, повтор |
| Панель действий | y 736, 328×56 на стекле: Текст, Скачать, Очередь |

Кнопка Play это единственный яркий объект экрана: заливка от `glow`, смешанного с белым на 50%, к `glow`, свечение снизу, чёрная иконка. Остальные кнопки на стекле или без фона.

Бейдж качества показывает реальный формат потока: `FLAC 24/96`, `FLAC 16/44`, `MP3 320`. По тапу тост с битрейтом.

### 8.5 Состояния загрузки (`dl`)

`idle` → `queued` → `downloading(progress)` → `done`. Повторный тап по `downloading` отменяет, по `done` показывает тост «Уже на устройстве». Одна и та же кнопка используется в строке списка (38 dp) и на панели плеера (30 dp).

## 10. Источники музыки и API

Требование: максимальное качество и скачивание треков. Список ниже собран поиском. Документацию Jamendo (developer.jamendo.com) я из этой среды открыть не смог, поэтому все параметры и лимиты надо сверить на их сайте, прежде чем строить на них.

| Источник | Что даёт | Ограничения |
|---|---|---|
| **Jamendo API v3.0** (основной кандидат) | Бесплатный `client_id`. Независимая музыка под лицензиями Creative Commons. По найденной информации стрим и скачивание доступны в mp3, ogg и flac, у трека есть флаг `audiodownload_allowed`. | Артист может запретить скачивание, проверять флаг. Часть треков с лицензиями NC / ND: в коммерческом приложении нельзя без отдельного соглашения. Лимит бесплатного ключа в источниках называют по-разному (35 тыс. запросов в месяц для некоммерческих приложений). Проверить. |
| **Audius API** | Бесплатный. Стрим mp3, эндпоинт `/tracks/{id}/download` с параметром `original` для оригинального файла. | Скачивание зависит от настроек артиста, требования к авторизации для загрузки я не подтвердил. Каталог другой, чем у Jamendo. |
| **Internet Archive** | Поиск и метаданные без ключа. Оригинальные файлы FLAC, Ogg, MP3. Живые записи, нетлейблы, общественное достояние. | Метаданные неоднородные, обложек часто нет, качество каталога разное. |

### SoundCloud и YouTube Music

Просьба была взять поставщика вроде SoundCloud или YouTube Music в максимальном качестве. Коротко: так, чтобы это было законно и со скачиванием, не получится.

| Сервис | Что известно | Что это значит для Cloudly |
|---|---|---|
| **SoundCloud** | Официальный API есть. По блогу SoundCloud for Developers, самостоятельная регистрация приложений снова открыта (пост от 18 мая 2026), но нужна подписка **Artist Pro**, и приложение принимает API Terms of Use. Сторонние страницы пишут, что регистрация закрыта. Это устаревшие данные, верить стоит официальным. | Реалистичный вариант как **дополнительный** источник, только для стриминга и только в рамках их условий. **Не проверено**: какое качество отдаёт API (по моим ожиданиям обычное, не lossless) и разрешено ли скачивание в приложении. Это решают API Terms of Use, их нужно прочитать до разработки. Скачивать можно будет в лучшем случае те треки, где автор сам включил загрузку. |
| **YouTube Music** | Публичного API для аудио нет. Источники пишут, что условия YouTube запрещают сторонний доступ к потокам, а загрузка и фоновое воспроизведение это функции платной подписки внутри их приложений. Официальные условия я не читал. | Я **не буду** проектировать приложение вокруг извлечения потоков из YouTube Music: это нарушение условий сервиса и авторских прав, и такое приложение не пройдёт Google Play. Официальный путь это встроенный плеер YouTube, но он показывает видео с рекламой, не качает и не играет в фоне, для этого дизайна не подходит. |

Самый близкий законный аналог SoundCloud по духу и API это **Audius**: каталог артистов, открытый бесплатный API, оригинальные файлы там, где артист разрешил скачивание. Поэтому порядок такой: Jamendo и Audius дают максимум качества и скачивание, SoundCloud добавляется позже как ещё один `MusicSource` для стриминга, если условия подойдут.

Что **не** брать:
- Spotify, Apple Music, Deezer, iTunes Search API: отдают в лучшем случае 30-секундные превью. Полный трек и скачивание они не дают.
- Неофициальные парсеры YouTube, Tidal, Deezer и подобные «скачиватели»: нарушают условия сервисов и авторские права. На них нельзя строить продукт, и такое приложение не пройдёт правила Google Play.

Ожидание нужно выставить честно: бесплатные API с загрузкой оригинала это независимая музыка и свободные лицензии, а не мейнстрим-каталог.

### 10.1 Собственный API Cloudly (набросок)

Для этого стоит завести тонкий слой над источниками. Клиент не знает про Jamendo и Audius, он говорит с одним интерфейсом:

```kotlin
interface MusicSource {
    suspend fun home(): List<Section>
    suspend fun search(query: String, filter: Filter): List<Track>
    suspend fun track(id: String): Track
    suspend fun streamUrl(id: String, quality: Quality): String
    suspend fun download(id: String, quality: Quality): DownloadRequest?   // null, если артист запретил
}

data class Track(
    val id: String, val title: String, val artist: String, val album: String,
    val durationSec: Int, val coverUrl: String,
    val streams: List<Stream>,          // codec, bitDepth, sampleRate, kbps, sizeBytes, url
    val downloadable: Boolean, val license: String?,
    val palette: List<Int>? = null,     // glow, echo, deep, если считает сервер
    val waveform: ByteArray? = null,    // 64 значения
    val lyricsLrc: String? = null,
)
```

HTTP-эндпоинты, если делаем свой бэкенд: `GET /v1/home`, `/v1/search?q=&filter=`, `/v1/tracks/{id}`, `/v1/tracks/{id}/stream?quality=`, `/v1/tracks/{id}/download?quality=`. Сервер заранее считает `palette` и `waveform` (клиенту это дорого), агрегирует источники через адаптеры и нормализует лицензии.

Рекомендация: начать **без бэкенда**, только с `JamendoSource` за интерфейсом `MusicSource`. Бэкенд добавить, когда понадобятся второй источник, предрасчёт палитры и текстов песен, или аккаунты.

Показывать в интерфейсе: лицензию трека и атрибуцию автора (требование Creative Commons), реальный формат потока.

## 11. Производительность и доступность

Бюджет:
- не больше 4 стеклянных поверхностей одновременно;
- `Modifier.blur` не использовать на больших анимируемых областях, свечение рисуется градиентами;
- зерно: один полноэкранный `drawRect`;
- значения `p` и углы читать в фазе draw / layout;
- миниатюры из Coil запрашивать нужного размера (176 px), большая обложка 640 px;
- волна рисуется в `Canvas` по готовым 64 значениям;
- Baseline Profile и Macrobenchmark на открытие шторки и прокрутку главной.

Доступность:
- уважать системную шкалу анимации: при 0 отключить вращение свечения, прыжки зерна, пружины заменить на мгновенные переходы;
- настройка «Уменьшить прозрачность» отключает стекло и зерно;
- у волны семантика `progressBarRangeInfo` + `setProgress`, кнопки с `contentDescription`;
- зона касания не меньше 48 dp;
- в режиме TalkBack размытие строк текста песни выключено;
- контраст по разделу 3.2.

Тактильность (где доступно): `HapticFeedbackConstants` для подтверждения скачивания, щелчок при пересечении порога шторки, лёгкий тик при перемотке.

## 12. План реализации

1. **Каркас.** Gradle, Compose BOM, Media3, Coil, Backdrop, Room. Тема: цвета, типографика, `Motion`.
2. **Дизайн-система.** `GlassSurface`, `GrainOverlay`, `Aurora`, `CoverPalette`, `LiquidIndicator`, кнопки. Экран-витрина для проверки на реальном устройстве (особенно стекло и зерно на OLED).
3. **Плеер.** `MediaSessionService`, `PlayerSheet`, обложка, волна, режимы.
4. **Экраны** на моковых данных: главная, поиск, медиатека.
5. **Источник.** `JamendoSource`, потоки по качеству, загрузки через WorkManager, состояния `dl`.
6. **Шлифовка.** Хаптика, Reduce motion / transparency, Baseline Profile, тест на слабом и на среднем устройстве.

Открытые вопросы:
- Минимальная версия Android. Стекло с линзой требует API 33, блюр с 31 (проверить по документации Backdrop). От выбора зависит, нужна ли запасная ветка.
- Тексты песен: откуда брать (LRC в API, свои, сторонний сервис). В прототипе тексты придуманы.
- Нужен ли свой бэкенд на старте.
